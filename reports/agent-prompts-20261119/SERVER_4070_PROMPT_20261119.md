The repo was previously run on a larger GPU. On about 12 GB, check every stage before any long run:

- 20 updates each of: S1 CineMA distillation, S2 MedNeXt-L teacher (with its U streams, i.e. after the labeled-only warmup is skipped for the probe), S3-SA codebook fit, A4-SA student step (PG + CBKD-SA), and later W2S-Match student step. Record peak memory (`torch.cuda.max_memory_allocated`) and seconds per update.
- Allowed memory measures, in this order, only if a stage OOMs: (a) the repo's existing activation recompute for teacher blocks (commit `df646fc`) and any equivalent checkpointing for the student; (b) `expandable_segments:True` in `PYTORCH_CUDA_ALLOC_CONF`; (c) running evaluation with a smaller sliding / per-slab batch if the evaluator supports it without changing outputs.

- Write `reports/server4070-20261119/PROBE.md`: memory, s/update, projected wall-clock per stage (updates × s/update × 1.15), total for Part A and Part B.
