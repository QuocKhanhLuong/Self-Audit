# DSS-US / SGSCN ACDC adaptation (2026-10-02)

- Architecture, optimizer, LR, losses, stopping, clustering, seeds and declared conventions are bound by the
  source profile's SHA-256 and are never redeclared.
- No real ACDC data, DINO checkpoint or GT was used. No full run was started.

## 3. Producer path (both methods)

```
frozen v12 record -> read_self_audit_historical_224_context_stack (hash-verified source, before any method code)
  -> central plane [224,224] float32 -> ACDC input conversion -> uint8 x3
  -> [GT firewall: ProducerAccessGuard, nothing under the image root readable] method
  -> anonymous int32 [224,224] raw IDs (unmapped)
  -> seal_raw_partition (cardiac_raw_partition.v1) per sample -> native_acdc run seal (access log, cohort, adaptation)
  -> external write-once receipt (outside the run root)
```

**The one ACDC input adaptation:** `acdc_historical224_central_plane_minmax_uint8_gray3_v1`.
- The frozen central plane is min-max scaled per plane (float64), then quantised to uint8 with
  `floor(255u + 0.5)`; a constant plane maps to 0. The grey image is replicated to 3 identical channels.
- It is deterministic and image-only.
- It is strictly necessary: both methods' locked input encodings decode 8-bit images, while the frozen ACDC
  contract delivers z-scored floats. Identical channels make BGR and RGB order irrelevant.

Provenance per run and sample:
- record identity and source SHA-256
- the decoded sources
- adaptation config hash (`baseline_config_hash`), source profile SHA-256, profile class and paper equivalence
- central-image and model-input hashes
- seed, code identity, repository, environment contract

Operational timing is excluded from the sealed payload.

## 4. SGSCN ACDC pipeline

There are 4 adaptations, one per runnable profile:
- `ph2_` / `sysu_us_paper_faithful_declared_conventions`: PAPER_FAITHFUL_WITH_DECLARED_CONVENTIONS
- `ph2_` / `sysu_us_official_reference`: OFFICIAL_REFERENCE

Each profile keeps its own LR (PH2 0.1, SYSU-US 0.05), architecture, losses, stopping, input encoding and
final-forward mode. Training is per slice at 224×224, and the output argmax is the raw map (no resize).

- **Seed:** the native `sample_seed(1, sample_id)`, unchanged, over the ACDC sample ID.
- **SYSU-US cohort:** the native `cohort_inventory` binding does not apply on ACDC; it is replaced by the frozen
  ACDC manifest hash, as declared in the adaptation.
- **Choice not made:** which LR/profile is primary for ACDC is your decision. All four profiles are provided.

## 5. DSS-US ACDC pipeline

One adaptation: `step2_dss_baseline_dss_paper_faithful_declared_conventions`. Its flow and settings:
- DINO ViT-S/8 from the pinned source with a hashed checkpoint.
- 224 = 28×28 patches of 8, so no crop is needed.
- Step I eigensegments (15) with the official background relabel.
- Official-fallback Step II (bbox crops, MiniBatchKMeans 15, seed 1).
- Nearest resize to the image, which is the identity here.

Declared conventions are unchanged. Step II clusters over a fit cohort:
- The fit cohort is exactly the run's selected records, sorted by sample ID.
- `run.json` records the cohort, so a raw map depends on the selected split.
- A 1–2 sample smoke run is therefore not comparable to a full split run.

As in upstream (`semantic_map[0] = 0`), a foreground segment clustered into k-means cluster 0 shares raw
ID 0 with the border-inferred background. This is official behaviour and is preserved.

Step I/CRF, preprocessing, affinity and Ours-step2 rows stay BLOCKED_PROTOCOL. They cannot be adapted, and a
test enforces this.

## 6. Track A: GT-free common adapter

The frozen `cardiac_adapter_v2` runs over every sealed raw map with the producer's own central plane; the
central plane's hash must match the one sealed with the raw map.
- **Guard:** runs inside the GT firewall, and `run_track_a` takes no GT argument.
- **Inputs:** only the verified raw maps, the image-only plane and the image-only record.
- **Output:** a sealed semantic artifact per sample (`cardiac_semantic_partition.v2`) plus a run index bound to the
  raw seal.
- **No method-specific fitting:** the adapter is method-independent and cluster-ID permutation invariant.

**ACDC_TRACK_A_STATUS = ADAPTER_READY.** It is instantiated from the existing contract. It has not been run on
real data, because no ACDC images are present.

## 7. Track B: `raw_id_majority_vote_v1` (GT-assisted diagnostic only)

- **Unit and grid:** one sample (2-D slice) at a time. The raw map is restored to the native grid with the frozen
  nearest-exact label inverse, which is the same pixel correspondence Track A uses; GT is never resampled.
- **Assignment:** each whole raw ID goes to the class with the most valid GT pixels (values 0–3).
  - Ties break in the order BG, RV, MYO, LV.
  - Many raw IDs may map to one class.
  - A raw ID is never split, and connected components are not split.
  - There is no Hungarian matching, no Dice optimisation and no class quota.
  - A raw ID with no valid pixels becomes VOID.
- **Metrics:** the same common metrics as Track A.
- **Isolation:** the seal receipt is verified before any GT read. Output lives only in its own directory, which may
  not overlap the raw or Track A roots. No producer or Track A code imports it, and a test enforces this.

**ACDC_TRACK_B_STATUS = EVALUATOR_READY.**
