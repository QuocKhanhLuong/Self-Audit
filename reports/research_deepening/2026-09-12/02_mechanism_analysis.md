## 1. The implementation contract, as the code actually states it

**Override.** `generate_coordinates` returns early when `coordinate_override is not None`, never calling the generator (`dynamic_window.py:299-323@9726e6d`); the override is validated, never clamped (`54-93@9726e6d`). Coordinates enter downstream only through two `grid_sample` calls on the key and value projections (`381-394@9726e6d`).

**Candidate logit and gate.** `candidate_logits = annotation_logits + sigmoid(update_gate) * delta_logits` (`annotation_expert.py:448-452@9726e6d`) with `gate_head = nn.Conv2d(C, 1, 1)` (`:348@9726e6d`) — one channel, hence **class-shared**. `depth = min(turn+1, 3)` (`:395-396@9726e6d`).

**Replay.** `functional_call` over detached parameters and buffers; only the supports may differ; `record_kind` must be `ordinary` and `audit_conditioning`, `offset_mode` and a `state_identity` digest must match or it raises (`annotation_expert.py:556-615, 468-488@9726e6d`).

**Solver.** One factual replay, a tolerance test, one `torch.autograd.grad`, then at most two candidate replays (`self_audit_net.py:341-353, 442-454, 511-516@9726e6d`; ceiling `MAX_CANDIDATE_CHECKS = 2` at `:59@9726e6d`). Objective: REGRESS-weighted cross-entropy toward the **pre-transition** `argmax` plus `lam`·mean squared displacement in feature pixels (`:276-291, 386@9726e6d`). Feasibility: fractional margin floor **and** explicit class identity over all thresholded predicted-FIX pixels (`:537-552@9726e6d`).

**Transfer (C3).** `candidate = retained + gate * innovation`, both detached (`self_audit_net.py:604-610, 645-646, 1427-1435@9726e6d`); a final preservation check can revert the row (`:620-642@9726e6d`).

**Operating point** (`configs/self_audit_full.yaml:41-69@9726e6d`): 96 channels, 4 classes, `window_k = 8`, `max_turns = 3`, `rho_feature_pixels = 1.0`, `lam = 1.0`, `lr = null`, thresholds 0.5, `margin_fraction = 0.5`, `replay_atol = replay_rtol = 1e-5`, `max_backtracks = 2`, bfloat16 AMP; image 256 with an `H/4 × W/4` FPN (`fpn.py:20, 45-54@9726e6d`), so the feature grid is 64×64 and one feature pixel is `2/63 ≈ 0.0317` normalized units.

Notation below: `A` = pre-transition logits, `B_f` = factual candidate, `B_cf` = counterfactual candidate, `g = sigmoid(u_f)` the recorded gate, `P` the realized factual supports, `Q` a proposal.

## 2. What exact replay identifies — and what it cannot

**Proposition 1 (what C1 certifies).** *Derivation.* C1 tests `|replay(P) − B_f| <= atol + rtol|B_f|` (`self_audit_net.py:346-353@9726e6d`). Because the override bypasses the generator, the replay evaluates the *same* function of `(features, A, audit evidence, turn/iteration ids, parameters, buffers, mode)` at the *same* point. C1 therefore certifies **numerical reproducibility and state identity** — that the counterfactual is computed by the same operator at the same operating point. It certifies nothing about the counterfactual's accuracy at `Q ≠ P`.

**Proposition 2 (the intervention is on a downstream variable).** *Derivation.* The generator is `G(state, condition, ids) → P`; the solver intervenes on `P`, not on `G`. So `B_cf` answers "what if the sampled support had been elsewhere", never "what if the model had predicted a different support" — intervening on a node's realized value with its structural equation severed. Attribution of a regression to a *learned geometry* is therefore not identified by this construction.

**Proposition 3 (C1's strictness is dtype-conditional, and the dtype is not fixed by the config).** *Derivation.* Training enables bfloat16 AMP (`configs/self_audit_full.yaml:67-69@9726e6d`). bfloat16 has 7 explicit fraction bits (8 bits of precision with the implicit leading bit), so consecutive normals in the binade `[2^e, 2^(e+1))` have absolute spacing `2^(e-7)` (relative spacing varies with the value) and the unit roundoff is `2^-8`; float32 has 24 bits of precision, unit roundoff `≈ 6e-8`. Which of the two applies to the *compared* tensors is not determined by the config: autocast covers some ops and not others, `candidate_logits` is formed by an add and a multiply over head outputs (`annotation_expert.py:448-452@9726e6d`), and whether the solver's replay runs inside the same autocast region depends on the caller. Two regimes follow, and only measurement can say which holds. **(i)** If the compared logits are bfloat16 with magnitude `≳1`, `atol = rtol = 1e-5` lies far below one ulp, so for those entries C1 behaves as an exact-match test and is sensitive to any reduction-order, tiling or kernel nondeterminism. **(ii)** If they are float32, `1e-5` spans many ulps and C1 is a genuine, fairly loose tolerance. The batch-composition discipline (`self_audit_net.py:311-317, 1269-1274@9726e6d`) is consistent with regime (i) being the design concern. **What to report instead of a pass rate:** the distribution of `c1_abs_error`/`c1_rel_error` (already computed, `self_audit_net.py:349-352@9726e6d`) together with the observed dtype of the compared tensors. I did not run anything, so I assert no pass rate.

**Also not identified.** The encoder, FPN, initial head and Auditor are outside the replay. A one-pixel trust radius smaller than the nominal residual-offset bound does not establish generator reachability: factual offsets may already lie near their limits, and outputs are jointly parameterized. Whether the generator can produce a particular proposal from this state remains unproved. History clearing limits repeated restitution, but an intervention can still affect the following ordinary turn and final rollout (Section 7).

## 3. C3: when it is convex interpolation, and what the gate does twice

**Proposition 4 (exact convexity conditional).** *Derivation.* Let `R` be the retained state. C3 gives `N = R + g ⊙ (B_cf - B_f)`. If `R = B_f` exactly, then

  `N = (1 - g) ⊙ B_f + g ⊙ B_cf`, with `g ∈ (0,1)` per pixel, shared across classes.

Per pixel `p`, for the factual winner `w` and any class `c`:
`N_w - N_c = (1-g_p)(B_f,w - B_f,c) + g_p(B_cf,w - B_cf,c)`.
If `w` strictly wins at both endpoints, each difference is positive and `w` strictly wins in the mixture. Ties require consistent tie-breaking and the actual runtime re-check. **Class-shared `g` is load-bearing**: with a per-class gate the two differences are mixed with different weights and the inequality fails in general.

**Where the premise holds.** `R = B_f` holds exactly for a freshly accepted row (acceptance assigns `state = candidate`, `self_audit_net.py:1090@9726e6d`, and the record is consumed the next turn). The code nevertheless only *tests* `|R − B_f| <= atol + rtol|B_f|` (`:356-358@9726e6d`). Under that weaker premise `N = convex_mix + (R − B_f)`, a perturbation `<= 1e-5 + 1e-5|B_f|`, so a protected pixel with margin below roughly twice that can flip. The code catches this empirically (`:620-642@9726e6d`) rather than by construction: the preservation *proof* is conditional; the *guarantee* is a runtime check.

**Proposition 5 (the gate is applied twice, and the correction is attenuated by `g²`).** *Derivation.* `B_f = A + g ⊙ Δ_f` with `g = sigmoid(u_f)`, and the replay recomputes its own gate, so `B_cf = A + g_cf ⊙ Δ_cf`. Substituting into C3 with `R = B_f`:

  `N = A + g⊙Δ_f + g⊙(g_cf⊙Δ_cf − g⊙Δ_f) = A + g⊙Δ_f + g⊙g_cf⊙Δ_cf − g²⊙Δ_f`.

Consequences. (a) The counterfactual delta enters multiplied by `g·g_cf` — a product of two sigmoids, systematically attenuated. (b) As `g → 0` restitution vanishes entirely: the pixels where the expert declined to update are exactly the pixels where correction is annihilated. (c) Only as `g → 1` does `N → B_cf`. (d) The factual delta acquires coefficient `g − g²`, maximal at `g = 1/2`. **The transfer weight is the original update gate, not a calibrated confidence or a quantity explicitly derived from the restitution problem.** The coefficient that would actually replace `B_f` by `B_cf` is 1, not `g`. This is a design coupling, not a bug: it buys Proposition 4's convexity at the price of a state-dependent, unprincipled correction magnitude.

**Proposition 5b (the gate threshold that decides whether a repair survives C3).** *Derivation.* At a REGRESS pixel let `r` be the pre-transition (restoration) class and `w` the factual winner, `m_f = B_f,w − B_f,r > 0` and `m_cf = B_cf,r − B_cf,w > 0` (the counterfactual actually repaired the pixel). By Proposition 4 the mixture's `r`-vs-`w` difference is `g·m_cf − (1−g)·m_f`, so the repair survives the transfer **iff**

  `g > m_f / (m_f + m_cf)`.

**Scope of Proposition 5b.** The displayed threshold is exact for the **pairwise** `r`-vs-`w` comparison, i.e. for two classes, or when `w` is the only competitor that can beat `r` in the mixture. With `num_classes = 4` the correct multiclass condition is over **all** competitors: writing `m_f^c = B_f,c − B_f,r` and `m_cf^c = B_cf,r − B_cf,c`, the mixture puts its argmax at `r` iff `g·m_cf^c > (1−g)·m_f^c` for every `c ≠ r`, i.e.

  `g > max_{c ≠ r, m_f^c > 0} m_f^c / (m_f^c + m_cf^c)`.

The pairwise form is a lower bound on the true threshold, so it *understates* how often a repair is lost at transfer. The same algebra with `A` in place of `B_cf` gives the direct-rollback threshold with `m_A^c` in place of `m_cf^c`. I make **no** general claim that `m_A^c > m_cf^c`, and therefore no claim that rollback flips at least as many REGRESS pixels; the two thresholds are simply different functions of quantities that must be measured per pixel.

**Testable consequence.** Among pixels actually repaired by `B_cf`, transfer survival follows the multiclass inequalities above, subject to ties and numerical tolerance. A zero aggregate loss of repairs does not falsify the algebra: all observed gates may exceed their thresholds. Across all pixels there is no general monotonic repair-rate inequality, because in multiclass prediction an intermediate convex mixture can select a class winning at neither endpoint.

## 4. Locally attainable corrections: Jacobian structure and partial bounds

Write the output of one expert call as `B(Q)` with `Q = (Q^(1),…,Q^(D))`, `D = depth <= 3`, each `Q^(d) ∈ R^{B×64×64×8×2}`.

**Dimension counting, and what it does not show.** *Derivation.* `delta_logits` and `update_gate` are produced at feature resolution and bilinearly upsampled (`annotation_expert.py:448-451@9726e6d`), so the effective output is 4 logits + 1 gate = 5 numbers per feature pixel against `2K = 16` coordinate knobs per depth (16–48 total). **This counting is necessary, not sufficient:** more inputs than outputs does not establish that the Jacobian has full row rank, nor that there is no rank obstruction. Attention weights are a softmax over the same `K` points that supply the values, the `K` supports of one query share one query vector, and neighbouring queries share the sampled maps, so the columns are structurally coupled and the local nullspace may be large. Rank, conditioning and nullspace dimension here are **empirical quantities** — requiring additional offline Jacobian-vector or vector-Jacobian probes; one scalar-loss backward does not determine the rank — and I did not measure them.

**Proposition 6 (a partial bound: coordinate motion is limited by local key/value differences).** *Derivation.* Coordinates enter only through bilinear `grid_sample` of the key and value maps. Inside one cell `∂v/∂x` is an interpolation of the two horizontal neighbour differences of `V`; likewise for `y` and for `K`. A one-pixel displacement therefore changes each **sampled key/value** by at most the local total variation of the corresponding map over the traversed cells. **This bounds the sampled quantities only.** Carrying it to the logits additionally requires: the softmax's sensitivity to the changed attention logits (bounded, but data-dependent through `a(1−a)` and through `‖q‖`), the value-weighted recombination, and Lipschitz constants for `refinement_residual`, `delta_head`, the `sigmoid` gate and the bilinear upsample — none of which I measured. So the honest statement is a *mechanism* for boundedness, not a numeric bound on the innovation.

**Degeneracy corollary, stated conditionally.** A sufficient condition for the local sampling derivative of one support to vanish is that `K` and `V` are constant over the `2×2` cells that support touches; the whole gradient for a row vanishes if this holds for every support of every query, at every depth, that feeds a REGRESS-weighted output — at which point the solver reports `zero_gradient` (`self_audit_net.py:499-508@9726e6d`). I therefore make **no** claim that large homogeneous mis-segmentations (cardiac or otherwise) are outside Candidate C's reach: a query sitting inside a homogeneous region can still have supports reaching its boundary, since the reach is up to `0.25 + 0.55 + 0.12` normalized units (`dynamic_window.py:135-138@9726e6d`), far beyond one pixel. What is supported: **where the traversed neighbourhoods are constant, the coordinate channel carries no first-order signal**, and `zero_gradient` counts alone cannot identify this cause because cancellations and downstream insensitivity can also produce zero gradients.

**Joint FIX-margin feasible directions.** With `F(Q)` the C2 objective and `m_q(Q)` the winning margin at protected pixel `q`, the constraint is `m_q(Q) >= γ·m_q(P)`, `γ = 0.5`. Linearizing at `P` gives a **feasible polyhedron** `{δ : ∇m_q(P)·δ >= −s_q}` with per-pixel slack `s_q = (1−γ)·m_q(P) >= 0`; it is a homogeneous cone only where every active constraint has `s_q = 0`. The solver never intersects its direction with this set: it takes `d = −∇F`, projects onto a box, and tests feasibility post hoc.

**Proposition 7 (when halving can and cannot restore feasibility).** *Derivation.* Along `Q(t) = P + t·d`, let `v_q = −∇m_q(P)·d` be the linearized violation rate. To first order the violation is `[t·v_q − s_q]_+`. With the full step at `t = 1` and the half step at `t = 0.5`, three regimes follow: if `v_q <= s_q` the full step is already feasible; if `s_q < v_q <= 2 s_q` the full step violates but the **half step is feasible**, so halving does restore feasibility; and if `v_q > 2 s_q` both fail. At `s_q = 0` with an outward direction `v_q > 0`, the middle window is empty and no positive step along that direction is feasible in the linearized model. My earlier unconditional claim that halving can never restore feasibility was wrong and is corrected here; it holds only at zero slack. The structural point survives in weaker form: the backtrack explores **one fixed ray at two fixed sizes**, so it recovers feasibility only inside a factor-of-two slack window and can miss feasible improving points that lie on the same ray at smaller `t`, or off the ray entirely.

**Counterexample C7 (feasible improving point exists; both probed points fail).** *Construction, 2-D, exact within the linear model.* Take one depth, one support, coordinates `δ = (δ₁, δ₂)` in feature-pixel units, `ρ = 1`. Let the linearized objective be `F(δ) = F(P) − a·δ₁ + λ‖δ‖²` with `a > 0`, so `∇F(P) = (−a, 0)`, the normalized direction is `d = (1, 0)` and the two probed points are `δ_full = (1,0)` and `δ_half = (0.5, 0)`. Let one protected pixel have `∇m_q = (−1, 0)` and slack `s_q = 0.2`, i.e. the constraint is `δ₁ <= 0.2`. Then `v_q = 1`, so `t v_q = 1 > 2 s_q = 0.4`: **both** probed points are infeasible and the row is recorded `infeasible` (`self_audit_net.py:597-598@9726e6d`) with zero innovation. Yet `δ* = (0.2, 0)` is feasible, lies inside the trust region, and improves the objective by `0.2a − 0.04λ > 0` whenever `a > 0.2λ`. A feasible, improving, in-region point exists on the solver's own ray and the three-choice probe cannot reach it. **What this shows and does not show:** it establishes incompleteness of the fixed-step-size probe under a linear model; it does not establish how often such configurations arise, which is an empirical question.

## 5. Audit of the optimization itself

**Proposition 8 (`lam` does not influence the search direction).** *Derivation.* The displacement term `λ·mean((Q−P)/step)²` (`self_audit_net.py:259-291@9726e6d`) is quadratic in `Q−P` with its minimum at `Q = P`, so its gradient at `P` is exactly zero. The single gradient is taken at `P` (`:444-454@9726e6d`), hence `∇F(P) = ∇CE(P)` regardless of `λ`; `λ` enters only the improvement test `objective_candidate < objective_before` (`:536@9726e6d`). **The minimal-change preference shapes no search; it only vetoes.** (This confirms the coordinator's derivation independently.)

**Proposition 9 (with `lr = null` the trust-region projection is inactive).** *Derivation.* The step is `d = −g_px·(ρ/max|g_px|)·step` (`:492-498@9726e6d`), so `|d| <= ρ·step` componentwise — exactly the box bound in `_project_supports` (`:238-242@9726e6d`). The clamp is a no-op, touching the boundary only at the argmax component; only the `[−1,1]` domain clamp can bite. The trust region is enforced by the normalization, not by the projection, which is meaningful only under an explicit `lr`.

**What C2 therefore is.** The research-facing equation is a constrained `argmin` over a trust region; the implemented object is a **selection among three fixed points** — the factual support (identity fallback, `self_audit_net.py:605-609@9726e6d`), the full normalized step, and its midpoint — the first feasible-and-improving candidate winning. Direction and both step sizes are fixed before any feasibility information is used; `λ` only screens. "Optimal" is unsupported; "a bounded, auditable, three-choice counterfactual probe" is supportable, and the gap between the two descriptions is the method's largest overclaim risk.

## 6. Constructive counterexamples

**(a) A coupled zero-slack constraint can block a descent ray.** Neighbouring outputs can share dependence on coordinates through spatial convolutions (`annotation_expert.py:337-347@9726e6d`). In a locally affine example, take a tied protected FIX pixel with zero slack and a descent direction whose margin derivative there is negative. Every positive step along that ray violates the constraint. This is an existence counterexample, not a claim that real boundaries systematically have such ties or that all directions are infeasible. Curvature can change finite-step behavior; C7 gives a separate explicit positive-slack example.

**(b) Noisy evidence can target undoing useful changes.** FIX and REGRESS evidence share a local head, which permits but does not prove correlated errors. A hypothetical uniform output `REGRESS=0.6, FIX=0.2` gives an empty protected set and a flat restoration weighting over the whole image. C2 then seeks previous classes everywhere. This shares rollback's target but is not the rollback algorithm: reachable corrections, constraints, step budget and gate can produce different directions. Measure innovation alignment rather than assuming convergence. No GT is supplied to the runtime proposal; the final predicted Auditor may still reject it.

**(c) Support ordering is not identifiable; point-set geometry may still be.** *Proposition 10, derivation.* Attention is `softmax_k(q·k_k)` then `Σ_k a_k v_k` (`dynamic_window.py:391-393@9726e6d`), both symmetric in the support index. So in **exact arithmetic** `B(Q) = B(π·Q)` for every `π ∈ S_K`. Three scope limits matter. (i) In floating point the reduction order may differ, so equality holds up to rounding, not necessarily bit-identically. (ii) `K! = 40320` counts **orderings of one point multiset**, not distinct spatial point sets; the geometry is one object with many labellings. (iii) The solver's displacement penalty and box are defined against the *ordered* factual `P` (`self_audit_net.py:238-242, 259-273@9726e6d`), so a permuted starting point changes which proposals are in-region — the symmetry of the forward map is not a symmetry of the solver. **What this invalidates:** any reading that attaches meaning to *which* support index moved, i.e. point-identity claims. **What it does not invalidate:** permutation-invariant descriptions — support density, spread, convex hull, distance-to-boundary distributions — or causal probes that intervene on the realized set and read the output. I withdraw my earlier claim that this destroys any interpretation of the geometry.

**(d) Output equivalence with rollback, and an oracle ceiling on the repair endpoint.** Both mechanisms produce `R + g ⊙ ν`: rollback `ν_rb = mask ⊙ (A − B_f)` (`self_audit_net.py:806-811@9726e6d`), Candidate C `ν_c = B_cf − B_f`. They coincide whenever the counterfactual reproduces `A` on the thresholded REGRESS set and `B_f` elsewhere. `ν_c` is restricted to changes of the coordinate-parameterized replay; its first-order approximation lies in the Jacobian image, while `ν_rb` has no such representation constraint; I assert **no** general norm inequality between them, since the reachable magnitude depends on unmeasured local structure (Prop. 6) and `ν_rb` depends on how far `A` sits from `B_f`. Their relative magnitude and alignment are measurable and should be measured.

**Proposition 13 (oracle-rollback ceiling).** `audit/targets.py:82-84@9726e6d` defines true REGRESS as previous-correct/candidate-wrong and true FIX as previous-wrong/candidate-correct. Restoring the previous hard label on the true REGRESS set therefore repairs all of it and changes no true FIX. No method can exceed this ceiling on that narrow endpoint. Candidate C's potential value must instead be established under noisy evidence, on additional useful changes, or on a measured utility/cost trade-off. Raw `B_cf` is a replayed network output, but the final gated interpolation is not guaranteed to belong to any learned output manifold.

Caveats: the oracle set is unavailable at runtime, and the shipped gated rollback need not attain the ceiling. Pixels wrong in both states are outside true REGRESS, but support changes can affect them indirectly; a multiclass soft interpolation can also select a third class winning at neither endpoint. Hard rollback has the exact signed-count identity derived in [01, D6](01_problem_formulation.md). Repair rate on a predicted mask conflates evidence selection and correction, so evaluate both separately under paired histories.

## 7. Premises, history clearing, and the turn budget

**Proposition 11 (acceptance adds no support information conditional on all its inputs).** *Derivation.* The Auditor consumes shared features, previous probabilities, candidate probabilities, their delta and entropies (`self_audit_net.py:1063-1070@9726e6d`), not `Q`. With a fixed deterministic Auditor, acceptance is determined by that complete input tuple and the threshold. Conditioning on it adds no information about `Q` beyond that tuple; conditioning on the candidate logits alone is insufficient for this statement. Acceptance does not certify support optimality or justify a particular trust radius. The radius is a proximity/budget choice, not a consequence of the gate decision.

A circularity is worth naming plainly: one network produces the `delta_q` that accepted the transition, the local REGRESS evidence defining the repair target, the local FIX evidence constraining it, and the `delta_q` that then judges the repair. No external arbiter, no runtime ground truth, and hence no guarantee of monotone improvement or a fixed point.

**Proposition 12 (history clearing plus `T_max = 3` makes this a one-shot mechanism).** *Derivation.* Rejection halts the row (`self_audit_net.py:1146-1147@9726e6d`). Turn 0 has no record, so every row goes ordinary and a record is built (`:1652-1669@9726e6d`). At turn 1 every still-active row is one whose turn-0 transition was accepted, hence eligible (`:1248-1255@9726e6d`) and on the restitution path. A restitution action marks `previous_kind` non-replayable and builds no record (`:1637-1651@9726e6d`), so turn 2 is ordinary again — and with `cap = 3` there is no turn 3 to consume the record built there. **Each surviving sample therefore receives at most one solver action per image, at turn 1**, the only exception being a C1/staleness fallback that re-arms it for turn 2. This is a one-shot undo of the immediately preceding transition; "iterative self-correction" is not supported by the control flow.

**A confound any A/B comparison must control.** When the solver does not settle, the innovation is exactly zero (`:604@9726e6d`), so the Auditor receives the retained state as its candidate. The row survives only if it emits `delta_q > tau` on that zero-change pair. Its sign and empirical distribution are unknown; no coin-flip assumption is justified. The no-op consumes an attempt that could otherwise have been an ordinary refinement, so it can alter subsequent opportunities and termination. Whether identical pairs were represented sufficiently in training must be checked, not assumed absent. Report attempted-turn/halt-turn distributions and `delta_q` on identity candidates.

## 8. Detachment and what the model can learn

`innovation` and `gate` are detached at `self_audit_net.py:645-646@9726e6d` and applied at `1429-1435@9726e6d`; only `retained_rows` carries gradient. The joint loss applies the annotation term to the **retained final state** of a `mode="self_audit"` rollout (`training/finetune_joint.py:232-250, 683-694@9726e6d`).

*Derivation of the consequences.* (i) At a restitution turn `∂candidate/∂θ = ∂retained/∂θ`: there is **no gradient path through the solver**, so no parameter is credited for *how* the counterfactual was chosen. This is not "no learning credit at all". The detached innovation is an additive shift of the state at which the next ordinary forward and the final annotation loss are evaluated, so upstream parameters still receive gradients — evaluated at a shifted operating point, with the shift treated as a constant. The distinction is between differentiating *through* the correction and being trained *downstream of* it; only the former is absent. (ii) The solver creates no direct differentiable objective for learning correctable geometry, although upstream ordinary computation can still learn under the shifted loss. (iii) The recorded outer `g` is detached on restitution; no explicit objective optimizes it as a restitution gain. This does not exclude indirect training effects through the retained state. (iv) A count of gradient-carrying expert applications per rollout (three under `current`, two under `candidate_c`) holds **only when every turn is accepted**; under the shipped self-audit gate rejection halts the row, so the realized counts are random variables and any claim of unequal optimization between arms must be made on measured per-sample counts, not on the cap. (v) A detached next-state is a *shifted evaluation point*, which is not automatically a train/inference exposure mismatch: the same shift occurs at inference. Whether it degrades learning depends on whether the shift distribution differs between training and deployment — unmeasured here. The repository's own counters already separate "attempts whose own forward is the trainable ordinary annotation generator" (`training/finetune_joint.py:395-418, 512-520@9726e6d`).

## 10. Strongest defensible statement, and what would invalidate it

**Defensible.** Candidate C is a *bounded, reproducibility-checked, **predicted-FIX-class-preserving** single-probe counterfactual intervention on the realized sampling support of one frozen, previously accepted transition, transferred as a class-shared convex interpolation toward the counterfactual.* The preservation claim is deliberately narrow: it is argmax preservation **at thresholded predicted-FIX pixels**, conditional on the retained state matching the factual output and on both endpoints agreeing on the winner there (Prop. 4), and backed at runtime by an explicit re-check (`self_audit_net.py:620-642@9726e6d`). It is **not** general output preservation: everything off the protected set may move, and the margin floor permits protected margins to halve. Two further properties hold by construction: the override makes the counterfactual computation the factual computation with one variable changed (Prop. 1), and the compute budget is hard-bounded at one gradient and two checks by the config type itself (`self_audit_net.py:59, 123-133@9726e6d`).

**Not defensible.** That the procedure solves a constrained optimization problem, or that its "infeasible" verdict certifies absence of a feasible improving action (Props. 7–9, C7); that acceptance licenses the trust region (Prop. 11); that *which* support index moved carries meaning (Prop. 10); that the mechanism is iterative (Prop. 12); that the gate is a principled restitution weight (Props. 5, 5b); or that the method can exceed oracle-masked hard rollback on the repair endpoint itself (Prop. 13).

**What would undermine historical necessity.** A precise, prespecified equivalence or superiority comparison showing that a correctly centered current-state intervention or a cheaper rollback control matches C's useful correction, harm and cost outcomes under matched histories would undermine the need for historical replay. An underpowered nonsignificant difference would not. C1 tolerance sensitivity diagnoses numerical implementation; by itself it does not invalidate the scientific temporal reference.

**What would undermine geometry necessity.** A fair feature scale/bias or additive-latent intervention matching C at a matched resource and preservation budget would show that coordinates have not earned their special role. Low rank, local-contrast dependence and zero gradients are diagnostics, not standalone falsifiers: a low-dimensional reachable set may still contain exactly the useful corrections. The decisive question is whether useful target directions are reachable and whether a competing intervention achieves the same utility more efficiently.

*Not a valid falsifier:* permuting the `K` supports and observing unchanged output. Proposition 10 predicts exactly that in exact arithmetic for a permutation-symmetric operator; it tests the symmetry, not whether the geometry matters. A permutation-invariant intervention (e.g. randomizing the support *set* within the trust region and comparing objective decrease against the solved set) is the version of that probe that carries information.

None of these were run; they are the observations that would settle the questions, not results.
