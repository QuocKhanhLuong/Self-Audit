# Wave 3: lifecycle and truthful commit reporting

Follow audit_plan and preserve wave1/2 work. Own unified trainer lifecycle, CLI initialization/resume failure coverage, WandbLogger finalization API and focused tests. No changes to training math, LR recipe, model, gate or data splits.

Wrap initialized execution in exception-safe lifecycle handling; exceptions propagate and subprocess exits nonzero. Handle training, validation, logging adapter errors, checkpoint, report, calibration, diagnostics, resume and post-config model/init failures. KeyboardInterrupt should also close telemetry and best-effort record interruption; do not claim SIGKILL/power loss can execute Python cleanup.

Write a minimal strict atomic failure artifact when possible with completed=false, schema_version, failure_stage, zero-based current epoch and explicit completed-epoch count, global_step/optimizer_step, exception_type and safe message, last COMPLETED validation, last checkpoint committed epoch, git/source/config/run identities. Never fabricate validation metrics after a partial validation. Preserve partial progress reports after every completed epoch and do not overwrite unrelated run artifacts. Failure-artifact write or logger cleanup errors must not mask original exception; report secondary errors to stderr.

W&B epoch-completed semantics must be after required checkpoint and progress-report commits, or explicitly named validation-only events. Console, report rows, checkpoint epoch metadata and W&B use same state/values and explicit LR meaning (post-step next-update LR vs last applied LR). Include schedule weights/mode, counters and measured Dice/gain fields only. Keep one W&B run when enabled. Always finalize with failure exit code on failure and truthful final summary completed/status; disabled/missing/mocked W&B must work. Log failures may be nonfatal telemetry errors if recorded explicitly; never silently claim remote success.

Full run completed=true is committed only after selected best binding, requested calibration, diagnostics and final report succeed. A failure after calibration produces truthful failed pipeline metadata; artifact should remain explicitly diagnostic and not be mistaken for a completed experiment.

Tests: subprocess injected checkpoint failure exits nonzero + failure JSON; failures at training/validation/report/calibration/diagnostics/resume/init; old report preservation on rejected output ownership; W&B mocked success/failure/disabled cleanup, original exception preserved if failure writer and finish also fail; per-epoch report survives later failure. Integrate shared strict atomic writer. Wave4 owns immutable selected-best/last transaction and exact resume details; leave clean hooks for that wave.

W2 logger APIs now include set_summary(summary_dict), finish(exit_code=None), telemetry_errors:list[str], failed_log_count:int, and last_error:Exception|None. Use portable string/count status fields in report/checkpoint metadata; never serialize last_error or logger.__dict__ directly. A primary training/checkpoint/report exception must always propagate nonzero even if telemetry/failure-writing also fails. If optional telemetry is degraded without a raised trainer exception, report that separately and do not claim remote logging success.
