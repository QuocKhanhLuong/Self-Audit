## Peak estimate

Use the completed full-label checkpoint/export file sizes as conservative allocation proxies. New A has the same model and J architecture, and 8,000 T exposures / 8,000 J updates, so checkpoint/export sizes are expected to be comparable; this is a storage estimate, not a claim of training speed or exact byte equality. The inspected file sizes are: selected T checkpoint 407,290,852 bytes; J `resume.pt` 161,515,341 bytes; `joint_best.pt` 53,823,709 bytes; teacher/student/fusion exports 1,531,842,573 / 49,027,361 / 1,584,661,401 bytes. The largest simultaneous export set is about 3,165,531,335 bytes. Counting T plus resume plus J best plus all three exports is 3,788,161,237 bytes. Add the complete current prepared folder (154,320,054 bytes) as an intentionally conservative allowance even though it already exists and will not be copied, plus 10% for manifests, metrics, receipts, logs, atomic temporary replacement overlap and filesystem overhead: projected incremental peak is about 4,336,729,420 bytes (~4.34 GB). Available free space then leaves roughly 3.03 GB.

Calculation: `(407290852 + 161515341 + 53823709 + 1531842573 + 49027361 + 1584661401 + 154320054) * 1.10 = 4,336,729,420`. Values are rounded to whole bytes for display. Atomic checkpoint replacement temporarily overlaps old and new checkpoint bytes, but the 10% allowance is sized to cover one similar checkpoint overlap plus ordinary metadata; simultaneous export writes are already fully counted. Real write growth from unrelated jobs, library/cache churn, or unexpected extra export revisions is not included.
