| What head/loss is trained? | **Projector + predictor/prototypes.** The projector is a 1x1 linear projection plus a two-layer SiLU MLP whose outputs are summed (default `projection_type: nonlinear`). The predictor has learnable student/local prototypes and EMA teacher/global prototypes. The loss is `smooth_loss + data_loss`: within-image and cross-image feature/label smoothness, plus cross entropy from student/local logits to hard teacher/global pseudo-labels. Only projector and predictor are passed to Adam. | Paper §3.2, Algorithm 1, §3.3 (pp. 6): student/teacher prototypes, EMA pseudo-labels, smoothness/data terms and total objective ([paper](https://arxiv.org/abs/2310.17874), source lines 311-389). | Whole cost components | `E_smooth = E_smooth^within + E_smooth^across`, using zero-mean high-level feature cosine closeness and cosine label penalty. The across term pairs each batch image with a random batch permutation and uses `b2`; the within term uses `b1`. `E_data` is patchwise CE with `argmax(A^t)` as the hard teacher target. The implementation computes the same two branches as positive intra-batch and negative inter-batch correlation terms, then adds local-prototype CE to the teacher-global target. | Paper equations (1)-(8), Algorithm 1, §3.3 ([paper](https://arxiv.org/abs/2310.17874), source lines 246-289, 318-338, 376-389). | GT labels used for clustering mapping / checkpoint selection? | **Yes for evaluation mapping and checkpoint selection.** Validation/test update a confusion matrix with `preds` and GT, then `compute()` applies `scipy.optimize.linear_sum_assignment(..., maximize=True)` (Hungarian matching) before mIoU/Accuracy. The validation metric is logged under `test/cluster/`; `ModelCheckpoint` monitors `test/cluster/mIoU`, saves the top-1 checkpoint, and `trainer.test(..., ckpt_path="best")` evaluates that selected checkpoint. Thus the released training path is unsupervised in its loss but label-informed in validation mapping/model selection. | Paper §4.1 says Hungarian matching aligns predictions to ground truth for all images (source lines 394-404); Appendix says hyperparameter tuning avoids cross-validation on labels (source lines 680-691), but does not document checkpoint selection. ## Caveats / unknowns

- The paper does not document the exact released-checkpoint training log, seed-to-checkpoint correspondence, or whether every reported number used the repository callback's GT-mIoU checkpoint selection. The code clearly implements that path, but paper-to-checkpoint provenance is unavailable.
- The paper's “without cross-validation on labels” appendix statement does not remove the code-level use of GT labels for validation Hungarian mapping and `ModelCheckpoint` monitoring; this is a separate, label-informed selection step.
- The repository has no explicit no-GT dataset/evaluation mode. Training loss ignores labels, but the standard Coco/Cityscapes/cropped readers open label files and the wrapper returns labels. A genuinely label-free run would require an input-pipeline change, which was outside this audit.
- The code's exact implementation routes gradients asymmetrically: local logits use detached projected features, global logits use detached global prototypes; `global_clusters` is EMA state. This matches the intended student/teacher split, but the paper does not spell out these implementation-level detach points beyond the pseudocode stop-gradient notation.
