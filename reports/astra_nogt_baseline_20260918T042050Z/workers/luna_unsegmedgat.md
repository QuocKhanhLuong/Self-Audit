# UnSegMedGAT primary-source audit

Audit date: 2026-09-18 (Asia/Ho_Chi_Minh)

Scope was restricted to the authors' paper, arXiv:2411.01966v1, and the GitHub repository linked from that paper: `https://github.com/mudit-adityaja/UnSegMedGAT`. The repository was cloned at commit `7f5a0e53bb11da7608c07af4f364140c3d6366cf` (`origin/main`, `Update README.md`, 2024-10-31). No training, benchmark, or production/config/test changes were performed; this is a static methods/code audit.

## DINO features and freezing

The paper says the input is passed through a pretrained small ViT “without any fine-tuning,” and that patch descriptors are the key features from the final transformer block (arXiv HTML v1, lines 59-64): [arXiv:2411.01966v1](https://arxiv.org/html/2411.01966v1#S2). It specifies DINO-ViT small, patch size 8, and feature width `C_in=384` (lines 106-110).

The official code agrees on the intended backbone and freezes it:

- `segment.py:38-50` sets `model_type = 'dino_vits8'`, creates `ViTExtractor` from the supplied DINO checkpoint, and uses feature width 384 when `log_bin=False`: [pinned segment.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/segment.py#L38-L50).
- `extractor.py:71-85` maps `dino_vits8` to `vit_small` with patch size 8 and sets `requires_grad=False` for every backbone parameter, then calls `eval()`: [pinned extractor.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/extractor.py#L71-L85).
- `extractor.py:87-98` loads the checkpoint and selects `state_dict[head]`; the constructor default at `extractor.py:30-31` is `head="student"`. The notebook points to `dino_deitsmall8_pretrain_full_checkpoint.pth` and the Facebook DINO download URL (`main.ipynb:204-218`): [pinned extractor.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/extractor.py#L30-L31), [pinned extractor.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/extractor.py#L87-L98), [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L204-L218).
- `main.ipynb:214-216` uses stride 4 and the final block/layer 11 with the `key` facet. `extractor.py:301-324` extracts the requested facet/layer and removes the CLS token. Thus the runnable notebook uses overlapping 8x8 patches at stride 4, not the non-overlapping `n=st/p^2` simplification in the paper: [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L204-L227), [pinned extractor.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/extractor.py#L301-L324).

Conclusion: the DINO backbone is a frozen small/DeiT-small patch-8 model, using the checkpoint's student weights by default; only the graph model is optimized. The paper and code do not establish a separate frozen teacher-versus-student comparison.

## Per-image optimization and objective

The paper states that regular UnSegMedGAT is optimized separately for each image with Adam for 60 epochs, initial learning rate `1e-3`, decay factor `1e-2`, and threshold `tau=0.3` (arXiv HTML v1, lines 106-110). It separately reports 300 epochs for ISIC-2018 and 60 for ColonDB, and the collective settings `T0=5,T1=5` for ISIC and `T0=15,T1=55` for ColonDB (lines 111-114).

The code path differs in material details:

- `segment.py:98-135` loops over `(image, true_mask)`, extracts features, creates `W`, and constructs the graph for each image. `segment.py:161-173` reloads a checkpoint for each image, creates `AdamW(lr=0.0001)`, and performs `range(epoch[0])` update steps: [pinned segment.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/segment.py#L98-L173).
- The official notebook sets `epochs=[55]`, `stride=4`, `alpha=0.5` for the shown CVC run (`0.35` is only a comment for ISIC), `activ="SiLU_GAT"`, and `bs=True` (`main.ipynb:204-227`): [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L204-L227).
- The collective cell uses one shared optimizer/model and `range(5)` updates per image (`main.ipynb:269-318`), saves `modelCVC.pt`, and then calls the per-image path with 55 further steps (`main.ipynb:358-362`). This visible CVC notebook run therefore has 5 shared updates per image plus 55 independent updates per image, whereas the paper reports `T0=15,T1=55` for ColonDB. The notebook comments allow loading a checkpoint for later collective passes, but the checked source does not prove that three passes were run: [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L269-L344), [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L348-L362).

The paper's loss is Eq. (8): negative relaxed modularity plus the collapse regularizer (arXiv HTML v1, lines 88-105). The implementation is direct in `gnn_pool.py:219-239`: `B=A-dd^T/(2m)`, `-trace(C^TBC)/(2m)`, and `(sqrt(k)/n)||sum_i C_i||_F-1`; `C` is the softmax output from `gnn_pool.py:209-217`: [pinned paper](https://arxiv.org/html/2411.01966v1#S2.SS2.SS2), [pinned gnn_pool.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/gnn_pool.py#L209-L239).

For the default NCut path, `util.py:76-99` row-normalizes the DINO features, forms dense cosine similarity `W=F_norm F_norm^T`, thresholds it at `alpha`, then divides by `W.max()`. This is the code counterpart of the paper's similarity threshold, but the notebook's CVC value is 0.5 and the paper's reported value is 0.3: [pinned util.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/util.py#L76-L99).

## Ground-truth use: naming, mapping, evaluation, and selection

The strongest finding is that the official notebook consumes ground-truth masks before feature extraction. It loads sorted image/mask paths and pairs them (`main.ipynb:44-56`); `cts` finds the foreground pixels in the mask and crops both the image and mask around that foreground (`main.ipynb:127-167`). In the collective run, `true_mask` is read, `cts(image, true_mask)` is called, and only then are DINO features and `W` computed (`main.ipynb:283-305`). The reusable function does the same at `segment.py:98-135`, where `masks` are a required argument and `cts` is called before `deep_features`: [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L44-L56), [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L127-L167), [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L283-L305), [pinned segment.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/segment.py#L98-L135).

Ground truth is also used for cluster-polarity mapping and evaluation. The notebook computes IoU against `true_mask` for both `mask0` and `1-mask0`, keeps the better score, and may replace the prediction with its complement (`main.ipynb:127-135`, `main.ipynb:332-343`). The same logic is in `segment.py:198-204`. This is a label-dependent mapping/evaluation rule, not merely an unsupervised post-processing choice: [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L127-L135), [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L332-L343), [pinned segment.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/segment.py#L198-L204).

The paper reports mIOU on binarized masks (arXiv HTML v1, lines 116-123), but does not disclose this GT-based crop or polarity-selection protocol in the methods: [paper evaluation section](https://arxiv.org/html/2411.01966v1#S3).

For output naming, the audited code derives filenames from the input image and directory names from hyperparameters (`segment.py:86-101`), and writes a separate `_true.png` output (`util.py:18-24`). I found no GT-dependent checkpoint name, output directory name, or automated model-selection loop in the repository: [pinned segment.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/segment.py#L86-L101), [pinned util.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/util.py#L18-L24).

Model/hyperparameter selection remains unresolved. The paper says threshold 0.3 was found “through experimentation,” that 300/60 epochs were “optimal,” and that SiLU was best (lines 109-114 and 116-118), while the notebook hard-codes values and has no train/validation split or selection procedure. Because masks are already used for cropping and scoring, the source does not allow ruling out GT-guided tuning; it also does not prove that the reported choices were selected by a separate held-out protocol.

## Cost beyond parameter count

The source does not report wall-clock time, FLOPs, peak memory, edge counts, or a reproducible cost table. The code nevertheless makes the non-parameter cost explicit:

- With the notebook's 224x224 input, patch 8, and stride 4, the extractor's patch-count formula (`extractor.py:244-250`) gives `55 x 55 = 3,025` graph nodes per image. `util.py:80-93` materializes the dense `F_norm @ F_norm.T` matrix, and `gnn_pool.py:226-235` materializes/uses a dense modularity matrix and matrix products. A 3,025x3,025 float32 matrix is about 36.6 MB before edge-index, graph activations, autograd, and AdamW state; this is a derived estimate, not a reported measurement: [pinned extractor.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/extractor.py#L244-L250), [pinned util.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/util.py#L76-L99), [pinned gnn_pool.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/gnn_pool.py#L219-L239).
- Each GAT/loss update repeats graph attention and dense loss work. The visible CVC notebook has 378 image/mask pairs (`main.ipynb:59-83` output) and 5 shared plus 55 per-image updates, i.e. 22,680 update steps if that cell and the subsequent `GNN_seg` call are run once. This count is derived from the checked notebook, not an execution result: [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L59-L83), [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L283-L318), [pinned segment.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/segment.py#L161-L173).
- The frozen DINO still incurs a full ViT forward per image (`extractor.py:47-49`, `extractor.py:233-251`); frozen means no parameter updates, not zero inference cost. Thresholding does not remove the dense similarity construction, and `util.load_data` scans the dense adjacency to create edges (`util.py:203-215`): [pinned extractor.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/extractor.py#L47-L49), [pinned extractor.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/extractor.py#L233-L251), [pinned util.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/util.py#L203-L215).
- The shown notebook enables bilateral refinement (`bs=True`); `bilateral_solver.py:152-176` builds a bilateral grid and runs conjugate-gradient solves with up to 25 iterations (`cg_maxiter=25`) per output: [pinned main.ipynb](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/main.ipynb#L204-L227), [pinned bilateral_solver.py](https://github.com/mudit-adityaja/UnSegMedGAT/blob/7f5a0e53bb11da7608c07af4f364140c3d6366cf/bilateral_solver.py#L152-L188).

## Audit status

Confirmed: frozen DINO small/patch-8 student checkpoint features; final-block key descriptors; per-image GAT optimization; modularity plus collapse objective; dense graph construction; GT-dependent cropping and polarity mapping; GT IoU evaluation; and substantial iterative/dense-graph/post-processing cost beyond parameter count.

Unresolved: the exact held-out protocol, if any, used to choose threshold/activation/epoch settings; whether additional collective passes were run beyond the visible `CVC_CL_pass1`; and any claimed runtime/memory/FLOP number, because neither the paper nor the official repository reports those measurements.
